写库、队列、长连接分成三层

业务服务负责落库和接口。消息队列把投递从写接口里拆出去。长连接机器只服务当时在线的人。群消息全群共用一条记录，客户端用序号记住自己的进度。

一条消息怎么走

客户端 │ 业务接口 长连接 ▼ ▼ 业务服务（写库、同步、钱包） 长连接机器（可多台） ├─ 数据库 消息和关系的正式记录 ├─ 缓存 会话摘要、在线位置、登录态 └─ 消息队列 ──只投给有人在线的机器──┘ 当时不在线：下次打开，按消息序号把缺的补上

群

插入一次，序号在这个群里递增。推送前先看哪几台机器上有本群的人。会话列表更新摘要。

私聊

同样有会话内递增序号。对方在线时，队列只打到对方那一台。对方不在线，记录留在库里等同步。

手机

本地保存会话、消息、好友、群和每个会话的同步进度。推送和同步写的是同一条记录。

序号和加密

打开应用时，先问哪些会话落后，再只取序号更大的消息，然后把本地进度往后挪。好友和群资料有自己的版本，没变就跳过全量。

业务 JSON 用一次性 AES 加密，密钥用服务器公钥包住，私钥只在服务器。上传文件不走这层。线上仍然使用 HTTPS。登录按账号和设备计失败次数，连续失败会锁定；新设备或失败达到次数后还要手机或邮箱验证码。信任设备有期限和数量上限。密码只存哈希，管理端可以再开动态口令。

用户端接口地图

业务接口为 POST，登录后携带访问令牌。向前补消息走同步。

部署要准备的组件

JDK 21、MySQL 8、Redis、RabbitMQ 是必须的。要上传文件就加 MinIO。要跨网通话就加 eturnal，并和后端使用同一把密钥。生产用 Nginx 对外。数据库、缓存、队列不要对公网开放。同机部署建议 8GB 内存以上。

数据库、缓存、队列和对象存储可以用容器一起拉起。跨网通话的中继要和业务服务使用同一把密钥，并填写服务器的公网地址。

定制开发

可以在现有模块上继续改：品牌和界面、业务字段与后台菜单、短信或已有账号对接、按你的服务器协助部署。群通话和手机厂商通知栏需要单独评估。说明使用场景、要改的端和预计上线时间即可。
